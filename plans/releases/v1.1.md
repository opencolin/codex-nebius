## Theme

Config correctness and project identity: make the generated config.toml load and work, point the project at the real upstream, and add changelog/ignore scaffolding.

## Rationale

Backward-compatible bug-fix + additive hygiene, so a MINOR bump. The repo exists to emit one correct ~/.codex/config.toml, and today it is wrong in ways verified against the installed Codex CLI 0.135.0: base_url embeds the full /v1/chat/completions path (docs already use the clean /v1 root at docs/reference/models.md:154, so the script disagrees with its own docs) and no wire_api is set. CRITICAL CORRECTION to three of the five council proposals: I empirically tested `codex --strict-config doctor` against a sandboxed config and `wire_api = "chat"` is REJECTED (config fails to load) while `wire_api = "responses"` LOADS. The guide's prose (CODEX_CLI_SETUP_GUIDE.md:140-143) saying responses is the standard and chat is deprecated is therefore CORRECT, and any item proposing wire_api='chat' would actively break config loading. We standardize on wire_api='responses'. We also remove the script's wrong-credential instruction ('Add your OPENAI_API_KEY to ~/.codex/auth.json', line 185 — this setup uses NEBIUS_API_KEY only), fix the dead nebius-skill guide URL the script prints (line 195), relabel the 'Nebius Fast (Mistral)' provider that actually points at Gemma (lines 87/105), correct the README's shashikant86 link to openai/codex, and add CHANGELOG.md + .gitignore. disable_tools is deliberately NOT reintroduced: it exists nowhere in the tracked tree (only in plans/ORCHESTRATION.md notes) and was removed after commit d7ad935; restoring an undocumented key from rolled-back history is out of scope. File ownership is strictly disjoint: the script item solely owns setup-codex-nebius.sh; the identity item solely owns README.md; the hygiene item owns only new files.
