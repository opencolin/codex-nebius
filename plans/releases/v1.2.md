## Theme

Make it verifiable and keep the docs site buildable: a HOME-sandboxed test suite, GitHub Actions CI, and a Mintlify navigation that matches reality.

## Rationale

Still backward-compatible/additive, so a MINOR bump. The v1.1 correctness fixes are only durable if enforced; the 'fix'/'oops' commits in git history prove broken edits reach main unchecked. This release adds a pure-bash test harness that always runs setup-codex-nebius.sh under HOME=$(mktemp -d) with a stubbed `codex` on PATH (the script's Step 1 hard-exits if `codex` is absent — verified — so CI must stub it), plus a GitHub Actions workflow (ShellCheck + tests + a nav-vs-files guard), and fixes the Mintlify site: mint.json lists 17 navigation slugs but only 6 backing docs exist (verified), and 5 of those 6 docs contain dangling intra-doc links to pages that do not exist. CORRECTION to two proposals: the docs are .md and Mintlify resolves BARE nav slugs (no extension) to .md or .mdx — there is NO requirement to rename .md to .mdx, and doing so risks breaking working pages; the fix is to PRUNE nav to the 6 real pages and repair the dangling links, not to rename. File ownership is strictly disjoint: the test item owns only new files under tests/; the CI item owns only files under .github/; the docs item owns mint.json plus exactly the 5 docs files that contain dangling links (docs/reference/models.md is intentionally excluded so it stays free for v2.0's model refresh).

**Files (only these):** `tests/run.sh`, `tests/README.md`

Create a test harness under tests/ exercising setup-codex-nebius.sh entirely inside a throwaway HOME. HARD REQUIREMENT: every invocation MUST set HOME=$(mktemp -d) (cleaned up via trap) so the real ~/.codex and shell profiles are never read or written. The script must be driven non-interactively with `printf 'testkey
n
' | HOME=$tmp bash setup-codex-nebius.sh` (feed a fake key, then 'n' to decline the connection test so no network call happens) — do NOT pipe </dev/null (verified to hit EOF and abort under set -e before config is created). Because the script's Step 1 (line 14) hard-exits if `codex` is not on PATH, the harness MUST prepend a temp bin dir containing an executable `codex` stub (a 2-line shell script printing a fake version like 'codex-cli 0.0.0-test') to PATH so tests are deterministic without the real CLI. Provide tests/run.sh (plain bash assertions, no external deps) as the entrypoint covering at minimum: (a) the script creates $HOME/.codex/config.toml and exits 0; (b) base_url has no '/chat/completions' and wire_api='responses' appears twice; (c) no OPENAI_API_KEY/auth.json text in the script; (d) idempotency: running twice into the same sandbox HOME leaves exactly one `export NEBIUS_API_KEY=` line in the written profile; (e) the entered key value is never echoed to stdout (capture output, grep for the fake key, expect none). Add an optional config-validity check: if a `codex` binary is genuinely present AND not the stub (detect via a CODEX_REAL env or `command -v codex` plus a version check), run `CODEX_HOME=$HOME/.codex codex --strict-config doctor` and assert it reports config loaded; otherwise skip gracefully. Add tests/README.md documenting the mandatory HOME-sandbox rule and the printf-driver pattern. Do NOT modify setup-codex-nebius.sh, mint.json, .github/, or docs.

Do NOT create or modify mint.json, tests/, docs, or the script; rely on the other items having produced tests/run.sh and a corrected mint.json (this release's docs item).
